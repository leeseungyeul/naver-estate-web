# 브라우저 자동화 실계정 분리 확인 (라이브 조사 전 의무 — 세션 351 실토큰 노출 사고)

브라우저 자동화(chrome-devtools MCP·playwright MCP 등)로 라이브 사이트를 조사·재현하기
전, 그 자동화 브라우저가 **사용자의 실제 로그인 세션과 분리돼 있는지** 먼저 확인한다.
분리 확인 없이 진행하면 실계정 쿠키·JWT 토큰이 조사 출력(대화 전사·로그)에 그대로
박제될 수 있다 — **전사에 남은 토큰은 회수 불가**, 로그아웃→재로그인(토큰 회전)만이 답.

## 함정 — "자체 프로필이니까 안전" 은 절반만 맞다

(상세: .claude/rules-detail/browser-automation-isolation.md §chrome-devtools MCP 영속 프로필)

## 시작 전 체크 (예외 0)

1. **자동화 브라우저로 대상 사이트 접속 → 로그인 상태부터 확인.**
   - 비로그인 = 분리 확인 완료, 진행.
   - 로그인돼 있음 = 실계정 세션 보유 중(레드 플래그). 진행 중단하고 2번으로.
2. **로그인 상태로 발견되면**: 사용자에게 먼저 보고. 격리 프로필(`--isolated` 등)로
   재시작하거나, 실계정 세션이 조사에 꼭 필요하면 **사전 고지 + 토큰·쿠키 원문 dump
   금지**(document.cookie·localStorage·Authorization 헤더 값을 출력에 찍지 않는다 —
   존재 여부·길이·앞 4자리 마스킹까지만) 조건으로만 진행.
3. **E2E 테스트 계정과 실계정을 혼용하지 않는다** — 라이브 조사에 로그인이 필요하면
   테스트 계정 우선.

## 브라우저 MCP 가 없어 크롬을 직접 띄울 때 (CDP) — 재사용 조건 (세션 414)

세션에 브라우저 도구가 하나도 없으면(`claude mcp list`·`enabledPlugins` 로 확인) 설치된 크롬을
`--remote-debugging-port` 로 띄우고 `frontend/node_modules/playwright-core` 의 `connectOverCDP` 로
조작할 수 있다. 디버그 포트는 **인증이 없어** 열려 있는 동안 이 PC 의 어떤 프로세스든 그 브라우저를
조종할 수 있으므로 아래를 전부 지킨다:

1. `--user-data-dir` 는 **세션 스크래치패드 아래 새 폴더**(시작 시 비로그인 = 위 체크 1번을 그대로 적용해 확인),
   `--remote-debugging-address=127.0.0.1`.
2. ⛔ **사장님이 평소 쓰는 크롬(기본 프로필)에 디버그 포트를 붙이지 않는다.**
3. 쿠키·스토리지·Authorization 헤더는 읽지 않는다 — 화면 글자와 입력 요소의 상태만 본다.
   인증키 등 비밀값이 찍힌 캡처는 작업이 끝나면 지운다.
4. 끝나면 로그아웃 → **CommandLine 에 그 임시 폴더명이 든 `chrome.exe` 만** 종료(크롬 전체 종료 금지) →
   임시 폴더 삭제 후 **삭제·포트 닫힘을 출력으로 확인**. 외부에 글을 올리는 등 되돌릴 수 없는 동작은
   제출 직전 입력값을 검증하고(커스텀 라디오는 `click({force:true})` 뒤 `.checked` 확인) 사장님 확인을 받는다.

## 토큰이 이미 노출됐다면

(1) 인정(변명 0) (2) 어느 계정·어느 세션 토큰인지 명시 (3) 해당 계정 로그아웃→재로그인
(리프레시 토큰 회전) 안내 (4) 본 룰에 사례 추가.

## 실계정 부수효과 — 쿼터를 차감하는 API 검증은 admin 계정으로 (세션 395)

로그인 상태 노출만이 위험이 아니다. 자동화 브라우저가 **사장님 실계정**으로 단지 클릭·"데이터 갱신"·실거래가 수집을
누르면 그 계정의 **일일 쿼터**(`user_profiles.daily_crawl_quota` 기본 5회/일, `daily_price_collect_quota`, KST 자정 리셋 —
`auth/permissions.py check_quota`)가 실제로 차감된다. 세션 395(2026-09-09)에 라이브 검증(단지 15111 크롤 폴링·모달 확인)으로
사장님 expert 계정의 크롤 쿼터 5/5 를 소진해, 사장님이 직접 쓰려 할 때 "일일 크롤링 한도를 초과했습니다" 를 보게 만들었다.

- 크롤·시세수집처럼 쿼터를 차감하는 경로의 라이브 검증은 **admin 계정**(`routers/live/crawl.py` — admin 은 쿼터 미적용)으로 한다.
- 사장님 실계정으로 해야만 하는 검증이면 **1회로 제한**하고, 검증 뒤 `rate_limit_counters` 의 `user:<id>:crawl:<날짜>` 카운트를
  읽어 몇 회를 썼는지 보고에 명시한다.
- 캐시 TTL 안의 재조회·이미 진행 중인 크롤은 차감되지 않으므로(신규 크롤 시작 경로만 차감) 같은 단지 재확인은 쿼터를 안 먹는다.
